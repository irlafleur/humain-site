5. Token Optimization: Shorter, Cheaper, Sharper

Eight habits to keep prompts short, reuse and summarize context, and understand cost and usage limits, without making answers worse.

Why bother?

  • Quality: focused context gives sharper answers (Lesson 4).
  • Limits: chat plans have usage limits that depend on the provider and plan, and they can change. Shorter work goes further.
  • Cost: if you ever use an API or build an agent, you're billed per token (OpenAI's docs: you pay per token, and both input and output tokens count).
  • Speed: OpenAI's docs also note that writing more tokens takes more time.

The goal is not to write tiny prompts. It's to remove words that don't help.

Eight habits

1. Say it once, say it plainly

Cut greetings, apologies, and repeated instructions. “Hi! I hope you're well. I was wondering if you could possibly…” becomes “Summarize this in 5 bullets.”

WordyTight
“I would really appreciate it if you could please help me write a short email to my landlord about the broken heater, and make it polite but firm.”“Write a polite but firm 80-word email to my landlord about a broken heater.”

2. Paste only what's needed

Need a summary of section 3? Paste section 3, not the whole 40-page document. Remove signatures, email chains, and boilerplate before pasting. (Also good for privacy.)

3. Set the output length

Output tokens add up, and for some models they are priced differently from input. Ask for “under 150 words”, “5 bullets”, or “table only, no intro”.

4. Don't re-send what's already in the chat

In one conversation, the AI already sees earlier messages. Refer to them (“use the table above”) instead of pasting them again.

5. Put the standing instructions in one place

If you retype the same 300-word instruction every day, save it as a Project instruction or a skill (Lesson 8). You'll stop retyping it, and it stays consistent. (Saved instructions still count toward the model's context when they're used. This saves your time and prevents drift, not the tokens themselves.)

6. Summarize and restart

Long chats pile up tokens and “context rot”. When a chat gets heavy, compress it and start fresh:

Summarize this conversation so I can continue in a new chat. Include: (1) my goal, (2) decisions made, (3) key facts and numbers, (4) what's still open, (5) any format or style rules I asked for. Under 200 words. Don't add anything that wasn't said.

Then open a new chat and begin with: “Context from a previous chat: [PASTE SUMMARY]. Next, I want to…”. Read the summary first. If it's wrong, fix it before you paste.

7. Match the model to the job

Many providers offer smaller, faster options alongside larger ones. For simple reformatting or classification, a smaller model is often enough. For hard reasoning, use the stronger one. Check your provider's current model list and pricing page. We don't name models here because they change often.

8. Be careful with “thinking” modes

OpenAI's help center notes that on some advanced models, reasoning tokens are extra “thinking steps” included before the final answer. If a model has a thinking or reasoning mode, it may use more of your limit. Turn it on for hard problems, off for easy ones.

Cost and limits, step by step

Chat plans (free or subscription)

You usually don't pay per token. You get a usage allowance that varies by plan and by model, and it can change. Look for the provider's plan page, not a blog post. We don't quote numbers here because they go out of date.

APIs and agent tools

Providers publish prices per million tokens, often with separate prices for input and output. The formula:

cost = (input tokens × input price + output tokens × output price) ÷ 1,000,000

Made-up example (not real prices)Suppose a pretend model costs $2 per million input tokens and $10 per million output tokens. A call with 3,000 input tokens and 500 output tokens costs (3,000 × 2 + 500 × 10) ÷ 1,000,000 = (6,000 + 5,000) ÷ 1,000,000 = $0.011, about 1.1 cents. Run it 1,000 times and it's $11. Replace the pretend prices with the real ones from the provider's pricing page.

Agents multiply tokens

An agent runs a loop (Lesson 1), and each loop step can re-send the instructions and context. A long-running agent can use far more tokens than a single chat message. Set a step limit, keep instructions short, and watch usage when you first run something new.

Caching (if you use an API)

OpenAI's help center lists “cached tokens” as reused tokens that are often billed at a reduced rate. If you build with an API, keep stable instructions at the start and changing data after them, and read your provider's caching docs for the exact rules.

Exercise

Exercise A: The 30% trim. Take one of your longest prompts. Cut 30% of the words without removing any fact, number, or constraint. Run both versions. Is the answer any worse?

Exercise B: Summarize and restart. Pick a long chat. Use the summarize prompt, read the summary, fix any mistakes, and continue in a fresh chat. Note how many messages it took before the first chat got fuzzy.

Exercise C: Do the maths. Find one real API pricing page (your choice). Write down the input and output prices per million tokens and the date. Estimate the tokens of a prompt of yours (characters ÷ 4) and an answer of 300 words (×1.33). Compute the cost with the formula above.

Exercise D: Limit-proof prompt. Rewrite your most-used prompt so it asks for a specific length and format. Save it in your prompt log.

Key takeaways

  • Remove words that don't help; keep facts, numbers, and constraints.
  • Paste only the needed section, cap the answer length, and summarize and restart long chats.
  • Chat plans have usage allowances; APIs charge per token. Always check the provider's current price or plan page.
